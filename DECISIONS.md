## Data and modelling (to be filled in as we go)

| # | Decision | Reason | Status |
|---|----------|--------|--------|
| D1 | Raw data in `data/raw/` is never modified | Reproducibility | DECIDED |
| D2 | Target = 30-day readmission: 1 if readmitted == "<30", else 0 | Standard value-based-care measure; actionable window | DECIDED |
| D3 | Patient-grouped train/validation/test split by `patient_nbr`; all encounters for the same patient stay in exactly one split. | 47,021 of 101,766 encounters belong to repeat patients; grouping prevents patient-level leakage. The three splits must all be grouped by `patient_nbr`. | DECIDED |
| D3a | Split protocol. Unit: patient (`patient_nbr`); all encounters of a patient stay in exactly one split. Applied after D10 and the fixed D5 rules, on the remaining encounters. Patient-level label for stratification only: 1 if the patient has any `readmitted == "<30"` encounter (among retained encounters), else 0. Patients are split about 70% / 15% / 15% (train / validation / test), stratified on that label, with a fixed seed (42). The label is used only to assign splits and is never a model feature. | Prevents patient leakage; stratification keeps the rare 30-day outcome comparable across sets. Encounter-level shares and positive rates will differ slightly from 70/15/15 and from each other because patients have different numbers of encounters; actual values are reported, not forced. | DECIDED |
| D3b | Required checks after splitting (read-only): no `patient_nbr` in more than one split; encounter and patient counts per split; positive rate per split; subgroup (race, gender, age) counts per split. Save the patient-to-split assignment table so the split is reproducible. | Verifies the protocol worked; flags small fairness subgroups early. | DECIDED |
| D3c | Role of each set. Train: fit all learned preprocessing and models. Validation: compare models, tune, choose the decision threshold, and run ablations. Test: used once, for final reporting only; never for any choice. Any cross-validation is patient-grouped (by `patient_nbr`), within the training data, with preprocessing re-fitted inside each fold. | Keeps the test set unbiased and prevents patient leakage in CV. | DECIDED |
| D3d | Seed is fixed before any results are seen. No seed selection based on performance. Seed-robustness checks, if done, use validation data only. | Prevents result-driven selection. | DECIDED |
| D4 | Column decisions for all 50 columns. Identifier/grouping only: `encounter_id` (never a feature), `patient_nbr` (grouping for the split only). Target only: `readmitted`. Exclude: `weight` (96.86% "?"), `examide`, `citoglipton` (constant "No"). Rare-drug special handling, not standalone features, contributing only via F2 (13): nateglinide, chlorpropamide, acetohexamide, tolbutamide, acarbose, miglitol, troglitazone, tolazamide, glyburide-metformin, glipizide-metformin, glimepiride-pioglitazone, metformin-rosiglitazone, metformin-pioglitazone. Keep with special handling (12): race, gender (3 Unknown/Invalid rows retained with special handling), payer_code, medical_specialty, diag_1, diag_2, diag_3, max_glu_serum, A1Cresult, admission_type_id, admission_source_id, discharge_disposition_id (categorical, after D10). Keep as is (19): age, time_in_hospital, num_lab_procedures, num_procedures, num_medications, number_outpatient, number_emergency, number_inpatient, number_diagnoses, metformin, repaglinide, glimepiride, glipizide, glyburide, pioglitazone, rosiglitazone, insulin, change, diabetesMed. | Based on observed counts and frequencies. The rare-drug cut-off (under about 1% non-"No") is a project-specific modeling judgment using column frequencies only, no target. Within-stay information is allowed under the discharge-planning assumption (no timestamps, so this is an explicit limitation). Whether race, gender and age are model inputs is decided in D7. | DECIDED |
| D5 | Data-quality rules: (1) "?" in retained categorical columns -> "Unknown". (2) "None" in `max_glu_serum` and `A1Cresult` -> explicit category meaning test not performed. (3) "Unknown/Invalid", "Not Available", "Not Mapped" etc. in coded ID columns are kept as meaningful categorical states, not numbers. (4) Missing diagnosis codes -> "Unknown"; no diagnosis is imputed. (5) Rare medication columns (under about 1% non-main value) get special handling, not standalone use (project judgment, not a universal rule). (6) No blanket mean/median/mode imputation. (7) No separate missingness indicators by default. | Imputing would fabricate patient data in a clinical tool. Fixed rules that use no target are safe before or after the split. | DECIDED |
| D6 | No outlier removal or capping for the eight numeric/count columns (`time_in_hospital`, `num_lab_procedures`, `num_procedures`, `num_medications`, `number_outpatient`, `number_emergency`, `number_inpatient`, `number_diagnoses`). Keep observed extreme values. | All values are non-negative integers with plausible observed ranges. High values can represent legitimate hospital utilization or encounter complexity. Generic IQR/z-score removal could discard valid clinical encounters. | DECIDED |
| D7 | Model inputs: `age_midpoint`, `payer_code` (flagged), `medical_specialty` (flagged). Audit-only (never in the feature matrix): `race`, `gender`, original `age` bracket. | Audit needs the originals; race and gender are not collected by the app; payer_code and medical_specialty may be useful but are proxy- and recording-habit-prone. Choices are judgments; none tested yet. | DECIDED |
| D7f | Ablations (with/without `payer_code`, `medical_specialty`, `race`) use grouped validation or cross-validation only, never the test set | Prevents the test set from influencing decisions | DECIDED |
| D7g | The 3 gender `Unknown/Invalid` rows are retained; reported in the audit but not interpreted (n = 3) | Gender is not a model input, so keeping them costs nothing | DECIDED |
| D7h | Limitation: `payer_code` and `medical_specialty` have ~40% and ~49% `Unknown` and no hospital ID; `Unknown` may reflect recording habits, and their availability at discharge planning cannot be verified | No timestamps or hospital identifier | DECIDED |
| D8 | Decision threshold and risk category cut-offs | Must be based on actual model results | PENDING (Stage 9/12) |
| D9 | patient_nbr and encounter_id are never model features | Identifiers; patient_nbr used only for grouping | DECIDED |

Raw count: 2,423 encounters (101,766 -> 99,343 before removing the 3 Unknown/Invalid gender rows). Applied before the split as a fixed rule that uses no target. | Cohort-eligibility decision, not leakage: patients who died or went to hospice cannot be readmitted in the usual sense, and the tool is not intended for them.
